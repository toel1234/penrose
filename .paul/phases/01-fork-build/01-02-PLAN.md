<objective>

## Goal
Replace every user-visible and system-integration Inkscape identity in the fork with **Penrose**, driven from one source of truth (`fork/cmake/ForkBranding.cmake` → `config.h` macros). Code namespaces, extension IDs, data-dir layout and license/attribution stay untouched.

## Purpose
Inkscape's name and logo are trademarked. PROJECT.md requires the fork to ship under its own brand, and its profile, D-Bus name, desktop ID and translation catalog must not collide with a system Inkscape. 01-03 (AppImage/Flatpak) needs final IDs and icons to package.

## Output
- `install/bin/penrose` and `install/bin/penrose-view` (CMake target names `inkscape`/`inkview` are kept; only `OUTPUT_NAME` changes).
- `penrose --version` prints `Penrose <version> (...)`.
- App-id `io.github.peter.Penrose`; the viewer uses `io.github.peter.PenroseView`.
- Desktop and metainfo files under those IDs, and hicolor icons named `io.github.peter.Penrose*`.
- User profile in `$XDG_CONFIG_HOME/penrose`, cache in `$XDG_CACHE_HOME/penrose`.
- Gettext domain `penrose` (`penrose.mo` installed).
- New Penrose logo, icons, about screens and startup/splash artwork in `fork/branding/`, installed in place of the Inkscape assets.
- Rebranded user-visible strings, `penrose.1` / `penrose-view.1` man pages, and `fork/scripts/verify-branding.sh`, which re-runs the whole AC sweep.

## Decided facts (not re-opened here)
- Product "Penrose", binary `penrose`, app-id `io.github.peter.Penrose`, config dir `penrose`, gettext domain `penrose`. GTK4 as built.
- This plan derives the viewer identity: product "Penrose Viewer", binary `penrose-view`, app-id `io.github.peter.PenroseView`. It is recorded in the SUMMARY.

## Worker model
- Task 1 and Task 3: code and string edits by deepseek/GLM workers.
- Task 2a (artwork): antigravity gemini-3.8, writing SVG source code. If the MCP returns empty output, as happened in 01-01, fall back to the `agy-gemini38` CLI.
- Task 2b (strings and install rules): deepseek/GLM workers.
- Opus reviews every task's diff and verify output before the next task starts.
