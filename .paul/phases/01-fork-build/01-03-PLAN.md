## Decision: AppImage approach
Manual AppDir assembly + `patchelf` + `appimagetool` (type-2), not linuxdeploy. Reasons:
- Our two non-system libraries (gtkmm 4.14 in `build/deps`, cairo 1.18.6 in `build/deps-cairo`) and `lib2geom`/`libinkscape_base` are known, so an explicit copy list is deterministic and reviewable.
- linuxdeploy walks `ldd` and pulls in a large, host-dependent set of system libraries, guided by an excludelist we would have to audit. It also rewrites RPATHs in ways that are harder to verify.
- Scope of the skeleton AppImage: it bundles everything that is NOT an Ubuntu 24.04-class system package, and uses the host's GTK 4 / glibmm / poppler etc. Portability to older distros (bundling the full GTK stack) is deferred and recorded.

- Task 4 (commit/publish): executed by opus directly. It is outward-facing and irreversible, so it is not delegated.
